# Development status — 2026-08-30

## What changed today

### Foundation / Phase 1
- Added a dedicated Aqara signature module using Aqara's documented Accesstoken/Appid/Keyid/Nonce/Time + AppKey + lowercase + MD5-32 algorithm.
- Added a central Aqara region registry for EU, US, CN, KR, RU and SG. The current OAuth client remains EU until region selection is designed and tested end-to-end.
- Added a central camera-model registry instead of keeping model IDs in the driver.
- Added shared exponential backoff for transient Aqara/network failures.
- Added secret-redaction helpers so credentials are not accidentally logged.
- Hardened Aqara device pagination with duplicate protection and a safety limit.
- Added Node unit tests for the Aqara signature and model discovery.
- Added GitHub Actions to run the unit tests on pushes and pull requests.
- Moved Flow action listeners from every device instance to the driver. This is important for multi-camera stability.
- Added explicit device methods for privacy mode, audio clip and recording export.
- Fixed the privacy-mode/onoff mapping so `onoff=true` means the camera is active and `privacy=true` means the privacy shutter/mode is enabled.
- Added camera health polling at a deliberately low 10-minute interval; no aggressive polling loop is used.
- Added lifecycle cleanup for health timers and RTSP video registrations.

### Recording / Phase 3 foundation
- Added a companion recorder design based on MediaMTX.
- Added a Docker Compose example for the recorder.
- Added a three-camera MediaMTX configuration example.
- Recordings are per-camera and stored as fragmented MP4 segments.
- The design explicitly keeps recording outside the Homey process.

### Storage / Phase 4-5 foundation
- Documented NAS as the primary storage target.
- Documented Google Drive as an optional off-site secondary target.
- Documented rclone as the preferred bridge for cloud copies from the recorder host.
- Added retention and event-recording requirements to the roadmap.

## What was tested

### Static/code tests added
- Aqara signature test against Aqara's published example vector.
- Signature test without access token.
- Known camera model discovery test.
- Unknown device rejection test.
- CI workflow added to run `npm test` on Node.js 22.

### Not tested yet
The following require a real Homey + Aqara developer account and cannot be truthfully marked as tested from GitHub alone:

- Aqara OAuth login on Homey.
- Real `query.device.info` discovery.
- Adding two or more real cameras in one pairing session.
- Real Aqara camera resource IDs for G2H/G2H Pro/G3/etc.
- Real Aqara snapshot/stream/recording endpoints.
- RTSP playback on the user's camera firmware.
- PTZ and two-way audio.
- NAS write access.
- Google Drive OAuth and uploads.

## Important architectural decision

The app will continue to support an arbitrary number of Aqara cameras. Camera identity is the Aqara DID; no global camera state is used. The recorder uses a separate path per camera. A failure in one camera must not stop the other camera pipelines.
